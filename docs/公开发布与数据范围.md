# 公开发布与数据范围

公开仓库包含项目源码、说明文档及 `data/` 根目录的正式清洗记录，使 demo、后端离线测试与数据库导入能够使用同一份快照。来源和字段适用范围随记录保留；accepted 只表示本地清洗验收通过，不代表已重新核验网页或确认实时价格。

## 留在本地的内容

以下路径由 `.gitignore` 排除，不进入公开提交：

- `.env` 与本地凭据；`.env.example` 仅保留无密钥模板。
- `.idea/`、`.vscode/`、本地 Streamlit secrets、虚拟环境和缓存。
- `data_raw/`：原始采集包、网页核对材料、SQLite、Excel 和原始游客评论。
- `data/auxiliary/`、`data/review/`、`data/excluded/`、`data/audit/`：辅助评论、待审/排除记录及审计明细。
- `work/`：临时生成物、私人备份和发布过程工具。
- `data_cleaning/wine_general_knowledge_20261111/`：由本地原始输入生成的增量目录。
- `database/*_report.json`：本地执行报告，仓库已有的 Neo4j 导入报告作为历史记录保留。
- 本地数据库转储、向量存储和日志。

这些文件未被删除；现有本地开发和清洗材料仍保留。

## 从公开仓库复现

1. demo 和 `tests/`、`database/test_scripts.py` 使用已公开的正式数据，无需原始采集包。
2. MySQL/Neo4j 导入均从正式数据读取。目标数据库和模型凭据自行配置，不从导入报告推断在线状态。
3. `data/manifest.json` 保留本地清洗发布的追溯信息。原始文件及审计文件在公开仓库缺席，不代表那些记录已被对外发布。
4. 若要重跑原始清洗、原始文件哈希检查或依赖原始材料的清洗测试，需要在本地另行准备有权使用的原始输入目录。
5. `data/` 使用 Git 的 `-text` 属性保留原始字节，避免 Windows 换行转换造成 manifest 校验失败。

产品、来源摘要和知识请结合原记录注明的证据形式与适用范围使用；公开仓库不包含原始网页或游客评论全文。
