# v0.1.0：后端框架与数据接入基线

发布日期：2026-11-06。状态：预发布版本，用于保存当前可回溯的开发基线。

## 本版定位

本版完成系统架构落地、正式数据接入和知识向量存储流程。当前系统仍处于功能完善阶段，不将数据库就绪或语言流畅视为问答质量验收通过。版本冻结发生在泛化列表查询修复之前。

## 代码与数据范围

- Python 后端 `qa/`、Streamlit 入口、命令行入口、配置模板和运行依赖。
- MySQL 只读事实仓库、Neo4j 图/知识仓库、模型接口与分批向量构建脚本。
- 数据清洗和数据库生成/导入工具、架构与数据规范、回归用例。
- `data/` 根目录的正式 JSONL、Schema、manifest 与说明/质量报告。
- 不提交本地 `.env`、真实密码/API Key、IDE 配置、原始采集资料、游客评论、待审核/排除数据、审计明细和临时文件。
- 不提交数据库存储文件、Embedding 向量或已创建的在线索引。新环境需要自行导入并构建向量。

当前正式数据包含 49 条来源、22 家酒庄、47 条产品记录、10 条参考报价、101 个辅助实体、191 条别名、138 条知识、538 条关系和 30 条专业评价。产品记录的年份/容量范围及未知值按正式数据保留；参考报价不等于当前售价。

公开数据范围及使用方式见 [公开发布与数据范围](../公开发布与数据范围.md)。

## 已实现能力

1. 页面通过函数调用问答服务，业务层独立于 Streamlit。
2. 支持规则覆盖范围内的实体查询、硬条件筛选、条件修改和上轮展示顺序指代。
3. SQL/Cypher 使用预设模板和参数；模型不能执行任意查询。
4. 事实回答保持业务 ID、年份、容量、品种及来源；知识生成检查引用和数值，失败时退回证据摘要。
5. 两库运行配置、项目归属和正式快照分开管理；连接失败不切换演示数据。
6. 知识向量写入记录模型、维度、正文及编码指纹，支持跳过已有有效向量和分批恢复。

## 本版修复

- `qa/data.py` 对齐 SQL 生成器保存别名 `raw_record` 的行为，包含派生 `alias_key`。
- `qa/neo4j_repository.py` 对相似度名称进行大小写无关比较，兼容 Neo4j 2026.10.1 返回的 `COSINE`，并继续拒绝真实维度、标签、属性或相似度冲突。
- 真实数据不一致的错误补充业务 ID 与差异字段，不输出连接凭据。

## 验证证据与边界

本版发布前执行：

```powershell
python -m unittest discover -s tests -v
python -m unittest discover -s database -p test_scripts.py -v
```

结果分别为 22 项和 23 项通过。测试不请求模型、不写入线上数据库。

本地开发环境此前完成 MySQL、Neo4j 和知识向量只读就绪验证，均为 `ready`；138 条知识的向量维度为 4096，索引为 ONLINE。该记录仅反映该开发环境，不意味着克隆仓库后无需配置，也不证明模型答案质量。

## 已知问题与后续方向

| 问题 | 当前表现 | 后续方向 |
|---|---|---|
| 无实体名称的列表问题 | 有数据仍可能要求补充名称，例如“有什么酒庄” | 区分浏览列表与唯一实体详情，补齐 MySQL 列表查询及回归 |
| 规则解析覆盖不足 | 复杂口语、比较或排除表达可能澄清或回退 | 改进结构化模型提示和后端校验后的路由 |
| 合格零售价缺失 | “200 元以内”不能给出有价格依据的推荐 | 补充经核验的单瓶报价后再启用预算能力 |
| 偏好排序未实现 | 记录“果香、柔和”等偏好，不生成量化评分 | 依据真实描述与效果评估补充排序 |
| 回答质量尚未系统验收 | 连通正常仍可能存在不合理澄清或检索不相关 | 建立覆盖实际提问的端到端评估集 |

本版不包含管理员页面、订单、支付、物流、会员、实时库存和跨设备会话存档。
