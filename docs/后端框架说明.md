# 后端框架说明

本框架对应 [系统架构设计](系统架构设计.md) 中的 Python 问答处理层与数据库访问层，并提供最小 Streamlit 接入入口。当前版本为 v0.1.0：已通过 22 项后端与 23 项数据库脚本离线回归，并在本地验证两库及知识向量就绪；实际回答质量仍需持续验收。泛化列表查询缺口尚未修复，详见 [版本说明](releases/v0.1.0.md)。

## 1. 调用方式

业务层不依赖 Streamlit，后续页面或其他 Python 调用方可直接使用：

```python
from qa.config import Settings
from qa.service import build_service
from qa.session import ConversationState

service = build_service(Settings.from_env())
state = ConversationState()  # 每个用户/浏览器会话创建一个，不能全局共享。
try:
    first = service.ask("找几款750毫升的干红", state)
    second = service.ask("要含赤霞珠的", state)
    third = service.ask("第二款是哪家酒庄的？", state)
    print(third.text)
    print(third.sources)
finally:
    service.close()
```

`build_service()` 只读取配置和正式数据，不主动连接外部服务。`ask()` 根据实际查询路径使用数据源。默认 demo 模式只读正式 JSONL；database 模式使用 MySQL 和 Neo4j。两种模式的选择是显式配置，不会在连接失败后互相切换。

`QAResponse` 的主要字段：

| 字段 | 含义 |
|---|---|
| `status` | `ok`、`empty`、`clarification`、`not_ready`、`error` |
| `text` | 用于展示的回答 |
| `intent` | 酒庄、产品、筛选、知识或澄清 |
| `products` / `wineries` | 本轮实际展示的结构化事实记录 |
| `evidence` | 本轮使用的知识片段及适用范围 |
| `sources` | 支撑本轮事实/片段的来源登记 |
| `effective_filters` | 合并历史与当前修改后的有效硬条件 |
| `active_entity_ids` | 明确指向的业务 ID |
| `notices` | 降级、偏好排序未启用等说明 |

`empty` 表示当前资料没有满足全部条件的记录，不等于市场上没有该产品；`not_ready` 表示相应数据或模型能力未就绪；连接/数据版本失败返回 `error`。

## 2. 模块边界

`understand.py` 生成 `ParsedQuery`；`service.py` 校验实体和条件、选择数据源、整理来源并更新会话；Repository 只执行预设查询；`answer.py` 组织展示内容；`models.py` 封装外部模型协议。

规则理解用于框架演示，覆盖明确名称/ID、干红/干白、单一容量、年份、单一已披露品种及 100% 品种、酒精度上限、预算上限/区间、删除条件和简单指代。它不是完整中文语义解析器：排除条件、复杂比较、多品种布尔组合、模糊名称纠错等仍需扩展；不能因此宣称五项功能已全部验收。

已预留 `ChatModel` 和 `EmbeddingModel` 协议。大模型理解必须返回经 Pydantic 校验的结构化 JSON；额外字段、未知枚举、非法单位范围、证据外数字或引用均不能直接进入查询/展示。模型输出不拥有数据库执行权限。

当前事实回答采用结构化模板，防止大模型改写年份、容量、品种或产品身份。知识回答可由模型输出“结论 + 本轮证据 ID”，再核对引用与数字；没有模型或校验失败时展示检索证据摘要。这些结构化检查不等于语义真实性证明，最终仍需人工对照适用范围和来源验收。

## 3. 配置

从项目根目录 `.env` 与进程环境变量读取配置；进程环境变量优先。`.env.example` 不含真实凭据，`.gitignore` 忽略本地 `.env`。配置校验错误、数据库错误和模型错误仅向调用方提供概括信息，不打印密码、密钥或原始 HTTP 错误正文。

| 配置 | 说明 |
|---|---|
| `QA_BACKEND` | `demo` 或 `database`，默认 demo |
| `QA_DATA_DIR` | 正式 JSONL 目录，默认项目 `data` |
| `QA_DATASET` | Neo4j 库内归属，默认 `wine-qa-system` |
| `QA_SNAPSHOT` | 启用的内容指纹；留空则使用正式数据实际指纹，填写时必须相同 |
| `QA_MAX_RESULTS` | 展示上限，默认 10，范围 1–50 |
| `QA_PRICE_ENABLED` | 默认 false；开启也不会跳过报价资格核验 |
| `QA_PRICE_MAX_AGE_DAYS` | 报价核验时效窗口，默认 30 天 |
| `MYSQL_*` | MySQL 连接信息，库名默认 `Wine_QA_System` |
| `NEO4J_URI/USER/PASSWORD/DATABASE` | Neo4j 实际连接信息与数据库名 |
| `NEO4J_VECTOR_INDEX` | 向量索引名，经过标识符白名单校验 |
| `LLM_BASE_URL/API_KEY/MODEL` | 独立的大模型服务配置 |
| `EMBEDDING_BASE_URL/API_KEY/MODEL/DIMENSIONS` | 独立的向量模型配置，不沿用大模型密钥 |
| `EMBEDDING_ENCODING` | 文本编码/权重版本标识，默认 `plain-v1` |
| `MODEL_TIMEOUT_SECONDS` | 单次模型请求超时，默认 30 秒 |

兼容适配器对查询与知识正文都发送原始文本，不自动添加模型专用前缀，也不擅自截断文本。需区分 query/document 编码的模型，应替换适配器并更新编码标识。维度按模型真实输出配置；程序不补零、不截断向量。

## 4. MySQL 事实查询与筛选

沿用 `database/01_schema_mysql.sql` 的表与视图，不新增不兼容的数据表。连接按请求创建只读事务，完成后回滚并关闭。SQL 中只有固定字段、JSON 路径和排序模板可以拼接，所有业务值通过参数传入；运行账号建议使用仅具查询权限的账号。

由于现有 MySQL 表没有数据快照列，首次实际问答会在同一只读事务中比对 10 张表的实体集合、真实列值与规范记录，拒绝遗留额外记录和与正式 JSONL 不一致的内容。通过后一分钟内复用校验结果。这是适合当前小数据量的接入方案；数据扩大后可改为离线发布版本登记及原子切换机制。

每次条件筛选同时检查：

1. `strict_product_filter_eligible`；
2. 每个目标字段的 `field_filter_eligibility`；
3. 字段的实际值；
4. SQL 返回后再次检查硬条件。

“干红”必须满足 `color=red` 与 `sweetness=dry`；“含赤霞珠”不能当作“100% 赤霞珠”，后者还要求完整配方、唯一品种及 100% 比例。产品产区使用产品自身的 `region_id`，不从酒庄所在地推断。未知年份、容量、酒精度或起泡状态保持未知。

价格功能默认关闭。将来启用时，查询合格零售价候选视图，并继续核对当前/严格资格、冲突、单瓶、人民币、规格范围、等值报价及核验时效。模糊“左右”基础规则按上下 20% 解释，并附带说明。没有合格价格时不能用参考价替代。

当前偏好仅进入会话与输出说明，尚未实现有依据的偏好排序；合格产品按稳定业务 ID 排列，不生成风味强度分数。

## 5. Neo4j 检索与向量构建

图查询限制 `qa_dataset`、`qa_snapshot`、正式审核状态、`retrieval_allowed` 及价格隔离标志。关联查询还检查实体和 `ABOUT` 关系的归属与快照。知识正文、来源、关联对象及适用范围需与本地启用快照一致，不能只相信旧导入报告。

`scripts/build_embeddings.py` 提供独立离线流程：

1. 验证正式数据与指定图快照的实体、关系集合。
2. 读取允许检索的片段，对正文哈希及已有模型/维度/编码版本进行判断。
3. 按批次请求 Embedding，校验数量、顺序、维度、有限值及非零向量。
4. 在写事务中重新检查正文与快照，写入向量、模型、维度、编码指纹、正文哈希和更新时间。
5. 创建或核对命名向量索引，等待其 ONLINE，最后核对所有正式片段向量。

同批事务失败会回滚当前批，已成功批次保留；再次运行会跳过有效向量，`--force` 强制重建当前快照。Schema 操作与分批写入不是一个全局事务，不能将中途日志视为已完成激活；在线查询在完整向量就绪检查通过前不提供知识语义问答。

为兼容 Neo4j 5.26 并落实“先按实体、主题和适用范围限定，再向量召回”，当前召回查询先过滤候选，再在 Neo4j 中精确计算余弦相似度并取前几条。向量索引仍由脚本创建和检查，但这版召回没有使用全局 ANN 后过滤；当前小规模数据适用，扩容后应替换为能保证范围过滤的 ANN 查询。余弦接近只表示检索相似，并不保证片段足以支撑回答。

知识中的任意命令、课堂任务或提示被当作资料文本，不能修改模型系统约束或触发代码执行。图中出现但 MySQL 实体目录中不存在的知识关联对象不会直接进入回答。

## 6. 连续会话

`ConversationState` 保存 `messages`、`current_topic`、`active_entity_ids`、`filters`、`preferences` 和上轮实际展示顺序 `last_results`。Streamlit 通过 `st.session_state` 持有独立对象，没有全局用户聊天缓存。

- 新条件只在继续筛选时继承历史条件；当前明确修改覆盖相应字段。
- “容量不限”等表达删除对应条件。
- “第二款”从上轮实际展示的产品 ID 数组定位，不重新按检索结果顺序推测。
- 多对象下的“这款”需要澄清；不存在的序号不能自动映射。
- “在这几款中”限定上轮结果；没有上轮结果时需要澄清，不能全库搜索。
- 缺少合格价格时保留预算条件，后续追问不会静默删除预算。
- 切换到知识话题会清除无关的筛选上下文，即使知识能力尚未就绪。
- 数据连接失败或澄清不会将一批失败结果覆盖成成功结果；开启新会话清空状态。

## 7. 后续运行与验收

本节是复现与后续验收命令。v0.1.0 的实际测试和本地就绪记录见版本说明；克隆仓库后需根据自己的数据库、模型配置重新验证。

```powershell
# 新增后端离线回归用例，无需在线数据库或密钥
python -m unittest discover -s tests -v

# 已有数据/导入脚本的独立回归，可另行执行
python -m unittest discover -s database -p test_scripts.py -v

# 本地正式数据及配置诊断，不连接数据库、不请求模型
python -m scripts.check_backend

# database 模式下只读检查两库；缺少向量会说明，不伪装已就绪
python -m scripts.check_backend --online

# 进一步要求正式知识向量完整就绪
python -m scripts.check_backend --online --require-vectors

# 实际窗口或命令行交互
python -m qa --interactive
python -m streamlit run app.py
```

回归用例覆盖组合筛选与产品顺序、条件删除、独立会话、预算停用后的条件保留、缺失值、100% 品种证据、歧义、空范围、查询参数化、报价时效、非法向量、伪造引用以及快照不一致。还需在后续实际部署中检查 MySQL 只读账号、Neo4j 实际数据库名、模型兼容性、向量构建和真实知识问答质量。

不包含管理员页面、订单、支付、物流、会员、实时库存、评论情感分析或跨设备聊天存档。框架不额外启动 FastAPI 服务；需要 Vue 接入时，可在 `QAService` 外增加接口层。
